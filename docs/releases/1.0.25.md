## ZSG Rooms 1.0.25

Stable release for Minecraft 1.16.1. These notes cover everything added since
the last stable release, **1.0.24**, including the 1.0.25 experimental build.

### More Repeatable Race RNG

All of these additions use the existing **Standardize Race RNG** rule. Turning
that rule off leaves their vanilla paths in use.

- **Nether natural monster spawning:** independent chunk, cycle, pack, and
  attempt RNG reduces variation caused by unrelated spawning activity. Pack
  selection is kept stable, and spawn-check rolls are isolated from earlier
  rejected attempts. This covers natural monsters, not just Blaze block spawners.
- **Initial fortress opportunity protection:** the first activated fortress gets
  eight initial pack-selection opportunities protected from the global monster
  cap. Collision, terrain, player-distance and other spawn checks still apply.
  Rejected selections also use an opportunity: this is not eight guaranteed mobs.
  Successful mobs still count toward the cap and can temporarily exceed it.
  Protection also expires after 4,096 evaluated fortress chunk cycles, does not
  refill on reload or rule toggles, and does not extend to later fortresses.
- **Gravel-to-flint rolls:** a separate deterministic sequence, preserving vanilla
  Fortune probabilities and normal Silk Touch behavior.
- **Unbreaking rolls:** independent sequences per item type, with vanilla
  enchantment-level and armor behavior. Using a golden pickaxe does not advance
  the iron-pickaxe sequence.
- **Portal wood lighting:** matching supported lava-and-wood setups beside
  complete, unlit Overworld portals get repeatable local ignition and fire-spread
  opportunities. The sequence is relative to the portal, rather than absolute
  coordinates or world age. Vanilla physical checks and Hard difficulty's
  existing-fire spread advantage remain; there is no forced lighting deadline.

### Customizable Match HUD

- New HUD settings available from Room Settings and the in-game pause menu,
  with a preview and locally saved preferences.
- Adjust background opacity, including no background, HUD scale and placement.
- Show or hide the HUD, header, player heads, and progress numbers.
- Limit visible rows and rotate through opponents instead of stacking everyone.
  By default, your own row stays visible while opponents rotate every five seconds.
  Rotation speed, row count, and whether to keep your row pinned are configurable.

### Performance and Diagnostics

- Reduced repeated natural-spawn seed hashing and created RNG streams only when
  needed, with regression tests for unchanged deterministic results.
- Reduced temporary collections, repeated sorting, and fortress-reference work.
  Fortress-protection work stops after the first fortress's allowance is exhausted.
- Cached the qualified Blaze spawner's deterministic key instead of rebuilding it
  on every update; player-range checks and spawn behavior are unchanged.
- Added spawn-rejection diagnostics behind Seed Debug Logging, with less work
  performed when debug logging is off.
- Added headless dragon-perch and portal-lighting test tools and expanded developer,
  game-rule, and HUD documentation.

### Dragon Behavior

Normal play retains the **1,300 dragon-tick grace period** from 1.0.24 before
perch standardization starts. The new benchmark can compare vanilla and
standardized behavior with different grace settings, but those test settings do
not change normal launches. This release does not add a dragon-spawn delay or
replace the dragon's flight/pathfinding AI.

### Important Limits and Updating

- Natural spawning is not a lockstep simulation. Different loaded chunks, player
  positions, collisions, or other rejected candidates can still produce different
  successful encounters. The fortress allowance is a tuning value, not a guarantee
  of identical mob counts, and intentionally relaxes the global cap initially.
- Wood lighting currently covers nearby static Overworld portal setups. Lava
  flow, weather, humidity, obstructions, build timing, external fires, and reopening
  an already-running setup can still cause differences. It does not force-load
  chunks or guarantee that every build will light. See the game-rule documentation
  for discovery and activity conditions.
- All runners should update together so they use the same RNG implementation.
  No new relay protocol or worker deployment is required for these additions.
- This is a normal stable release, so the optional in-mod updater can offer it.
  Older versions remain playable.

### Verification

Clean local build passed with **188 unit tests**, plus six headless Minecraft
wood-lighting comparisons covering lava ignition, existing-fire spread, translated
setups, staggered starts, difficulty changes, extra native attempts, and a
`doFireTick` pause. Full MultiMC modpack compatibility still depends on the other
installed mods; these checks are not a guarantee for every mod combination.
