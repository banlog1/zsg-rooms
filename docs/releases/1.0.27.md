# ZSG Rooms 1.0.27

## Three New Hosted Seed Banks

**ZSG Rooms Desert Temple**, **ZSG Rooms Village**, and **ZSG Rooms Shipwreck**
are now available alongside the existing FSG filters. Seeds are searched offline
and served to the host as needed, so runners do not need to run the new filter
searches themselves or download the full bank. The host's next seed stays
private until launch.

- **Desert Temple:** checks the four chests for at least seven iron, or four
  iron plus three diamonds. A terrain model rejects heavily buried temples.
- **Village:** checks non-abandoned plains, desert, or savanna villages for at
  least four iron-ingot equivalents in their own smith chests. The intended
  remaining iron comes from a golem; natural golem presence is not guaranteed.
- **Temple and Village:** use surface-lava opportunities instead of requiring
  a ruined portal, with a modeled multi-source water area within 48 blocks.
- **Shipwreck:** checks resources for starting tools and portal entry, food,
  and a nearby wooded island or coastline. It uses a modeled ravine-entry
  opportunity, not a guarantee of an exposed ravine in every world.
- **Nether:** reuses ZSG's bastion, fortress, route and loot checks. Stables
  bastions must also contain a good gap and a triple-chest rampart.

The public service is configured by default. No Java arguments or local server
are needed. Hosts who previously used localhost should open **Settings > Seed
Bank**, clear the server URL, and save. Explicit custom URLs remain supported.
An Internet connection is required for the host to fetch seeds.

At release preparation, the live bank contains **48,687 seeds**: 22,336 temple,
1,301 village, and 25,050 shipwreck. More seeds can be added without a mod update
or taking the active bank offline. These are model-based filters, not promises
of block-perfect terrain or loot in every mod combination.

## Safer Surface Lava Routes

New temple and village bank worlds try to provide **two usable surface lava
pools in different directions** during initial loading. Qualifying natural
pools are kept; missing pools use deterministic, irregular Minecraft-style
lake shapes rather than square basins.

Placement prefers locations within 96 blocks of the structure and can expand
to 128 blocks maximum. Each pool must be near a suitable natural water area
within 48 blocks. Preparation never adds water and avoids structures, trees,
the spawn area, and unsafe terrain. If only one safe pool is possible, it keeps
that one; if none is possible, it leaves terrain unchanged and logs a warning.
Reopening a played save does not refill collected lava.

This applies only to the new temple and village bank profiles, regardless of
the RNG or spawn-proximity toggles. **These are modified racing/practice worlds,
not vanilla-verifiable runs, even with the Regular Verifiable preset.** Original
FSG filters and shipwreck worlds are not affected by this pool preparation.

## Shared First Nether Entry

Added an optional **Shared First Nether Entry** game rule, off in all presets.
It uses the seed's original Overworld spawn as a common destination-search
reference and deterministic initial portal orientation. Small differences in
where runners build their first portals therefore do not change those inputs.

Fresh same-seed resets repeat the first-entry placement. Return trips and later
entries retain vanilla linking. Nether preloading follows the common reference
when applicable. This is independent of RNG standardization, and matching
placement still assumes matching Nether terrain and existing portals. A portal
built far from the reference may not link back to the original Overworld portal.

## Replay Performance Mode

Added optional **Performance Mode** in Replay Settings > Recording, off by
default. Enable it before recording to skip unchanged synthetic player-metadata
updates and avoid unnecessary equipment-update allocations. Movement remains
full-rate, and incoming terrain, entity, sound and other network packets are
retained. Savings depend on the run; this is not stronger compression or reduced
recording distance.

The optional replay companion remains at **0.1.0**. The README now includes
replay setup and hosted-bank instructions. Offline bank tools also support
resumable parallel searches, duplicate prevention, and incremental uploads while
the existing bank stays available.
